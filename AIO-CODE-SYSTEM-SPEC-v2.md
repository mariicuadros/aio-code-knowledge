# AIO CODE — Digital Entity Operating System, phase 2

**Entity:** AIO-001 · **Canonical internal type:** `DigitalEntityOperatingSystem`
**Decision date:** 2026-09-27 (Colombia) · **Status:** operating architecture in development
**Creator:** Marii Cuadros · **Primary public brand:** AIO CODE

## Definition

AIO CODE is a **Digital Entity Operating System**: a coordinated set of identity records, evidence rules, provenance, content relationships, observations, measurements and operational procedures for building and maintaining a digital entity across platforms. It includes a research and implementation **methodology** as one component; the methodology is no longer the top-level identity of AIO-001.

“Operating system” names the way this ecosystem is organized and run. It does **not** mean a computer operating system, a finished SaaS platform, an AI model, or privileged access to third-party search or recommendation systems. AIO CODE does not guarantee indexing, recognition, ranking, citation, recommendation or commercial results.

## External-system stages

The Observatory treats **indexation, retrieval, entity resolution, entity representation, citation and recommendation** as distinct stages. A system retrieving AIO CODE does not establish that it resolved the right entity; recognition or a correct description does not establish citation or recommendation. Recommendation is evaluated as a separate outcome under the recognition rubric, never silently included in a single visibility result. The system observes external outputs under recorded conditions and cannot infer a provider's internal mechanism from a response.

## Phase boundary

**Phase 1** built the initial entity and its infrastructure and produced documented results: specific search and AI sessions identified or described Marii Cuadros and AIO CODE and displayed citations to public sources, including observations before the Vercel Entity Home. Its historical questions, screenshots, logbooks and AI responses keep their dates and original wording. The September 28 same-day comparison (`observatory/reports/AIO-001-POST-BLOGGER-T0-20260928.md`) additionally records Perplexity selecting the current system definition and citing Vercel. **Phase 2** operates the connected system, adds content under provenance controls, measures changes after publication and tests transferability with other entities. The recorded phase-1 appearances are results of those sessions; a new name for the architecture does not establish which intervention caused them.

## Validation and sale boundary

What can be shown now: implemented records, governance, content architecture, local retrieval, the limits of the partial baseline, and dated external observations of identification and citation. What still requires evidence: the effects of new content, repeatability across independent entities, longitudinal changes in external systems, answer accuracy and willingness to pay. Services can be designed and piloted without claiming those future results in advance.

## Change control

Do not alter frozen prompts, snapshots, or third-party response text to match the new wording.
