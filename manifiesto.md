# AIO CODE — Manifesto

## Una investigación sobre identidad, inteligencia artificial y visibilidad digital

AIO CODE nace de una pregunta:

> **¿Qué ocurre cuando una identidad digital se construye deliberadamente como un sistema coherente de información y posteriormente es observada por motores de búsqueda y sistemas de inteligencia artificial?**

La pregunta comenzó como un problema práctico de visibilidad para una creadora.

Con el tiempo, se convirtió en una investigación sobre la manera en que las tecnologías digitales encuentran, relacionan, recuperan e interpretan información sobre personas, proyectos y entidades.

AIO CODE existe para estudiar ese proceso.

---

# I. La identidad digital es un sistema

Una persona no existe digitalmente únicamente dentro de una red social.

Su identidad puede encontrarse distribuida entre:

- perfiles;
- publicaciones;
- sitios web;
- repositorios;
- entrevistas;
- plataformas profesionales;
- bases de datos;
- documentos;
- contenido audiovisual;
- comunidades digitales.

Cada elemento constituye un nodo.

La relación entre esos nodos puede construir una representación más amplia de una misma entidad.

AIO CODE estudia esa red.

---

# II. Una entidad debe poder distinguirse

Internet contiene millones de personas, marcas y proyectos.

Los nombres pueden repetirse.

Las identidades pueden confundirse.

Las fuentes pueden ser incompletas.

Los sistemas pueden recuperar información perteneciente a entidades diferentes.

Por eso una de las preguntas centrales de AIO CODE es:

> **¿Qué información permite que un sistema distinga una entidad de otra?**

La investigación estudia nombres, atributos, relaciones, fuentes, datos estructurados y conexiones entre plataformas como posibles variables dentro de este proceso.

---

# III. La coherencia precede a la optimización

AIO CODE no parte de la idea de que una identidad deba construirse únicamente mediante palabras clave.

La prioridad es la coherencia.

Una entidad debe mantener una representación consistente de:

- nombre;
- identidad;
- profesión;
- áreas de actividad;
- proyectos;
- relaciones;
- fuentes;
- presencia digital.

La optimización, cuando exista, debe construirse sobre una identidad real y verificable.

---

# IV. La información debe poder rastrearse

Una afirmación sobre una entidad debe poder relacionarse con una fuente.

Por eso AIO CODE documenta:

- qué se publicó;
- dónde se publicó;
- cuándo se publicó;
- qué cambio se observó;
- qué sistema fue utilizado;
- qué hipótesis se formuló;
- qué resultado apareció.

La documentación forma parte del experimento.

---

# V. Observación no significa causalidad

Una aparición después de una publicación no demuestra automáticamente que la publicación haya causado esa aparición.

Una coincidencia temporal puede tener múltiples explicaciones.

Por eso AIO CODE distingue entre:

**Observación**

Lo que ocurrió.

**Hipótesis**

Una posible explicación de lo ocurrido.

**Evidencia**

Información que permite evaluar la hipótesis.

**Conclusión**

Una interpretación respaldada por suficiente evidencia.

Esta distinción es fundamental para el desarrollo del proyecto.

---

# VI. Cada sistema puede comportarse de manera diferente

Los sistemas de inteligencia artificial no necesariamente utilizan las mismas fuentes, mecanismos de recuperación, modelos o procesos de actualización.

Por lo tanto:

> **Un resultado observado en un sistema no debe considerarse automáticamente reproducible en otro.**

AIO CODE estudia las diferencias entre sistemas como parte del experimento.

---

# VII. La memoria conversacional no equivale a reconocimiento de entidad

Una conversación puede proporcionar información temporal a un modelo.

Eso no significa necesariamente que esa información forme parte de una representación pública o recuperable de una entidad.

Por esta razón, las pruebas del proyecto procuran diferenciar entre:

- contexto proporcionado durante una conversación;
- información recuperada desde fuentes externas;
- información previamente conocida por el sistema;
- información que aparece en búsquedas independientes.

Esta distinción permite diseñar experimentos más controlados.

---

# VIII. Los datos estructurados son una hipótesis experimental

AIO CODE utiliza tecnologías como:

- Schema.org;
- JSON-LD;
- `sameAs`;
- relaciones entre entidades;
- metadatos;
- documentación estructurada.

Estas herramientas se utilizan como parte de la investigación.

El proyecto no asume que su implementación produzca automáticamente reconocimiento por parte de modelos de lenguaje.

Su función dentro del experimento es evaluar si una representación explícita y coherente puede facilitar determinadas formas de descubrimiento, asociación o recuperación de información.

---

# IX. La red de nodos

AIO CODE experimenta con una identidad distribuida entre diferentes plataformas.

Cada nodo puede cumplir una función diferente:

- documentación;
- publicación;
- comunicación;
- experimentación;
- distribución;
- archivo;
- representación profesional;
- expresión creativa.

La investigación observa qué ocurre cuando esos nodos mantienen relaciones consistentes.

---

# X. La persona permanece en el centro

AIO CODE no pretende reemplazar la identidad humana mediante una construcción artificial.

El objetivo es estudiar cómo una persona real puede representar de manera más clara su identidad dentro de un ecosistema tecnológico complejo.

La tecnología es una herramienta.

La identidad pertenece a la persona.

La información debe permanecer fiel a ella.

---

# XI. El caso de estudio

**Marii Cuadros** es la creadora de AIO CODE y su principal caso de estudio.

Su identidad reúne diferentes dimensiones:

- artista;
- creadora;
- modelo digital;
- Community Manager;
- curadora musical;
- música y cultura DJ;
- creadora de contenido;
- investigadora independiente.

AIO CODE estudia cómo estas diferentes dimensiones pueden coexistir dentro de una representación digital coherente sin reducir la identidad de la persona a una sola categoría.

---

# XII. La investigación permanece abierta

AIO CODE no considera cerradas sus hipótesis.

Cada resultado puede producir una nueva pregunta.

Cada contradicción puede modificar una teoría.

Cada experimento puede cambiar la metodología.

El proyecto está diseñado para evolucionar con la evidencia.

---

# XIII. Principio de transparencia

Los resultados favorables y desfavorables forman parte de la investigación.

Los experimentos que no produzcan el resultado esperado también deben documentarse.

Una metodología únicamente registra aquello que confirma sus expectativas.

Una investigación registra también aquello que las contradice.

---

# XIV. El propósito

AIO CODE busca comprender una transformación que apenas comienza:

> **La transición desde una Internet organizada principalmente alrededor de páginas y motores de búsqueda hacia un ecosistema donde sistemas de inteligencia artificial pueden convertirse en intermediarios entre las personas y la información.**

En ese entorno, la pregunta ya no es únicamente:

> “¿Cómo aparezco en una búsqueda?”

También es:

> **“¿Cómo es representada mi identidad cuando un sistema intenta explicar quién soy?”**

AIO CODE investiga esa pregunta.

---

# Principio final

**No estamos intentando fabricar una identidad.**

Estamos intentando comprender cómo una identidad real puede ser:

**encontrada → diferenciada → relacionada → interpretada → representada.**

Marii Cuadros es el caso de estudio.

AIO CODE es el laboratorio.

La evidencia es el criterio.

La experimentación es el método.

Y la investigación permanece abierta.
