# Account Registry

Canonical registry policy for official accounts and infrastructure belonging to the AIO CODE ecosystem.

## Purpose

Create a stable relationship between an entity and its official digital surfaces so that an account can be recovered, replaced or audited without reconstructing the ecosystem from memory.

## Entity ownership model

| Entity | ID | Role |
|---|---|---|
| Marii Cuadros | MC-001 | Person / canonical real-world entity |
| AIO CODE | AIO-001 | Research project / experimental lab |
| NUX | NUX-001 | Fictional/narrative entity |
| Twin MC-001 | Twin-MC-001 | Digital representation/extension of MC-001 |

## Registry fields

Each account record should contain, where safe:

- platform
- handle / public identifier
- canonical URL
- associated entity ID
- account purpose
- creation date (if known)
- status
- recovery owner
- last security review

Do not store passwords, authentication codes, recovery codes, private email addresses or private phone numbers in this registry.

## Current ecosystem surfaces

The registry should cover, as applicable:

Instagram · TikTok · YouTube · GitHub · Hugging Face · Vercel · Spotify · Medium · Substack · X · Threads · Bluesky · Pinterest · Facebook · Bilibili · domain/DNS infrastructure.

## Evidence status

Account relationships should be classified as Observed, Corroborated or Verified. Do not convert assumptions into facts.

## Continuity rule

A platform account is one surface of an entity, not the entity itself. Loss of a surface must not destroy the identity, provenance or historical record of the ecosystem.
