# Security Incident Response Protocol

## Scope

This protocol covers account compromise, unauthorized access, impersonation, content tampering, loss of access, platform restriction and infrastructure failure.

## Sequence

1. CONTAIN — secure the affected account/device and stop further unauthorized access.
2. PRESERVE — retain original records, timestamps, platform notices and relevant system metadata privately.
3. VERIFY — distinguish observed facts from assumptions.
4. RECOVER — use the platform's official recovery and appeal mechanisms.
5. RECONNECT — restore canonical links and ecosystem references.
6. DOCUMENT — record the incident using neutral factual language.
7. REVIEW — identify the control that failed and strengthen it.

## Evidence classification

- Observed — directly recorded evidence.
- Corroborated — supported by more than one independent record.
- Verified — confirmed through an authoritative source or platform record.
- Hypothesized — proposed explanation not yet established.
- Unknown — unresolved.

## Privacy rule

Incident records containing personal data, private communications, credentials or identity documents remain private. Public documentation should describe controls and architecture, not expose sensitive evidence.

## Recovery principle

The purpose of this protocol is continuity and protection of the ecosystem, not attribution or retaliation.
