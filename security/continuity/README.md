# Ecosystem Continuity

The objective is that no single account, platform or service becomes a single point of failure for the ecosystem.

## Three-layer model

### 1. Public layer

Safe-to-publish identity and architecture:

- canonical entity IDs
- entity relationships
- public account URLs
- public provenance statements
- content IDs
- project chronology
- recovery architecture

### 2. Private archive

Retain outside this public repository:

- original media and project files
- private account/recovery information
- platform emails and recovery records
- invoices/contracts where relevant
- detailed security evidence
- sensitive identity material
- backup codes and credentials

### 3. Independent backup

Maintain a second independent backup of critical private material. A backup that depends on the same account or platform is not sufficient continuity.

## Recovery pack

For each critical platform, the private recovery pack should be able to establish:

1. the canonical entity
2. the relationship between entity and account
3. historical account ownership/control evidence
4. representative original content
5. relevant publication history
6. the canonical Entity Home
7. the appropriate official platform recovery path

## Recovery principle

The ecosystem should be recoverable even if one platform disappears, an account is temporarily unavailable, or a social profile has to be recreated.

## Security review cadence

Review critical accounts periodically for:

- two-factor authentication
- recovery methods
- active sessions/devices
- connected applications
- administrator/collaborator access
- domain/DNS access
- backup availability

Never record secrets inside this repository.
