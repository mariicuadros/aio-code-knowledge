# Content Integrity

## Purpose

Preserve authorship, chronology, identity relationships and reproducibility of ecosystem content without exposing private originals.

## Content identity

Every important published creative asset should receive a stable content ID.

Examples:

- `MC-IG-001` — Instagram creative
- `MC-TT-001` — TikTok publication
- `MC-YT-001` — YouTube publication
- `NUX-001-C01` — NUX narrative content
- `AIO-001-C01` — AIO CODE research content

A single creative work may have multiple platform records while retaining one canonical creative identity in the content registry.

## Integrity record

For important original assets, maintain privately:

- original source file
- creation/export date
- source project when available
- cryptographic hash when useful
- associated entity ID
- content ID
- publication records

The public layer should expose only non-sensitive metadata and references.

## Hash principle

A cryptographic hash can act as an integrity fingerprint for a privately retained original. The original file does not need to be published for the hash to be useful as a comparison record.

## Rule

Do not treat an AI-generated representation as an independent real-world person. Twin MC-001 remains a digital representation/extension of MC-001; NUX remains a fictional/narrative entity.
